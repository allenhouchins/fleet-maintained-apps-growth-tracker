## Workflow

1. **Daily Update** (12:00 PM UTC):
   - `.github/workflows/update-data.yml` runs
   - Uses GitHub API to fetch commit history (no cloning required)
   - Analyzes Git history of `ee/maintained-apps/outputs/apps.json`
   - Generates `data/apps_growth.csv`
   - Generates `index.html` with embedded data
   - Generates `README.md` with embedded charts
   - Commits and pushes changes

2. **Deployment**:
   - `.github/workflows/deploy-pages.yml` runs on push when `index.html` or `data/apps_growth.csv` changes
   - Deploys `index.html` to GitHub Pages
   - Website automatically updates

## Files Explained

- **main.go**: Main script that uses GitHub API to pull data from fleetdm/fleet (no git clone needed)
- **generate_html.go**: Builds `index.html` plus the two app data files. The page
  draws its charts as inline SVG (no Chart.js) and keeps only the chart series
  inline; the app list is fetched after first paint and the per-app detail only
  when a card is clicked, which keeps the document around 56 KB instead of 1.5 MB.
- **generate_readme.go**: Generates README.md with embedded charts and statistics
- **data/apps_growth.csv**: Time-series data (date, app_count, apps_added_since_previous)
- **data/apps_index.json**: Name, slug, platform and version per app — what the grid paints
- **data/apps_detail.json**: Description, installer URL and signing/hash info, keyed by slug — what the modal shows
- **index.html**: The page. Chart series are inlined; app data is fetched from the two files above, so it must be served over HTTP (not opened via file://)
